# 截图气泡 —— 实现说明

> 面向后续开发者/协作者的逻辑说明。本文描述截图暂存功能「做了什么、怎么工作、关键参数在哪、改哪里」。
> 与 [说明.md](说明.md) 相互独立，需要先了解项目全局（LSPosed 模块、双进程模型、Provider 配置桥）时参考该文。

---

## 一、功能总览

**定位**：把「一张截图暂存起来，短时间后随时再看」做成一整套流程：截图 → 分享给本 App → 系统悬浮气泡显示缩略图 → 点击展开全屏查看。

**典型场景**：点单后、取快递/取餐时，先把取餐码/取件码截屏并「分享给复制Mi达」，气泡常驻屏幕边缘；需要出示时点一下气泡即可展开大图，不用重新打开相册找图。

**核心链路**（一笔带过，细节见后文）：

```
用户在其他 App 截屏
   ↓  系统截图悬浮窗点「分享」→ 复制Mi达
[ShareReceiverActivity]  Intent.ACTION_SEND(image/*)
   ↓  SnapshotStore.save：复制到 App 私有目录 supermi_snapshots，回收旧图
   广播 com.example.supermi.SHOW_SNAPSHOT（带 FileProvider URI）
   ↓  system_server 内 HookEntry 注册的接收器
[OverlayBubble.showSnapshot]  更新截图队列 → 重建悬浮气泡窗口
   ↓
悬浮气泡（TYPE_SYSTEM_ERROR，顶部居中，与复制气泡同位置体系）
   ↓ 点击缩略图（带着该图的屏幕位置/尺寸）
[SnapshotViewerActivity]  透明窗口 → 从气泡位置放大展开全屏查看
   ↓「取消展示」/上滑返回/定时到期
删除 App 缓存截图（按开关决定是否同时删除相册原图）
```

**为什么能不开 App 就显示**：截图气泡不是 App 前台页面，而是 LSPosed 模块注入 **system_server** 后，由模块内的 `OverlayBubble` 用系统 Context 创建的 `TYPE_SYSTEM_ERROR` 悬浮窗。App 进程只在「收到分享」那一刻被拉起（`ShareReceiverActivity`），把图片存好、发一条广播就结束；之后气泡由 system_server 里的代码持有，任何时刻都在。

## 二、工作链路（分步）

### 2.1 收图：分享进本 App

- **入口**：`ShareReceiverActivity`（`exported=true`，透明主题），`AndroidManifest.xml` 中注册了 `ACTION_SEND` + `image/*` 过滤，因此系统截图悬浮窗的分享列表里会出现「复制Mi达」。
- **取图**：优先 `Intent.EXTRA_STREAM`，其次 `clipData` 第一项；顺手 `takePersistableUriPermission`。
- **保存**：`SnapshotStore.save(context, uri, mime, maxCount, deleteOriginal)`：
  1. 复制到 `noBackupFilesDir/supermi_snapshots/snap_<时间戳>_<随机8位>.<扩展名>`；
  2. 复制前先 `cleanup` 按 `maxCount`（1~3）回收旧文件；
  3. 复制后再 `cleanup` 一次，保证磁盘和气泡一致；
  4. 反查分享 URI 对应的相册原图路径（见 2.4），写入同名 `.orig` 伴生文件；
  5. 反查截图拍摄时间（`resolveCaptureTime`：优先 MediaStore 的 `DATE_TAKEN`/`DATE_ADDED`，失败时从 `Screenshot_2026-...` 文件名解析），写入 `.orig` 的 `taken_ms=` 字段；
  6. 单文件上限 30MB，复制失败/空文件立即删除。
- **通知 system_server**：构造 `com.example.supermi.SHOW_SNAPSHOT` 广播，携带 FileProvider URI、原图路径 `snapshot_orig_path` 与截图时间 `snapshot_taken_ms`，`setPackage("android")` + 签名权限 `com.example.supermi.permission.SHOW_SNAPSHOT`；App 侧先对 `android` uid `grantUriPermission`。**分享 Intent 本身拿不到截图来源 App**（只能看到分享面板的信息），来源由 system_server 按设置从文件名识别或用截图时间反查（见 2.2）。

### 2.2 显示：system_server 内的悬浮气泡

**HookEntry** 启动时（延迟 0/3 秒各注册一次，防竞争）在 system_server 注册两个广播接收器：

| 广播 | 处理 |
|---|---|
| `SHOW_SNAPSHOT` | `OverlayBubble.showSnapshot(uri, origPath, takenMs)` |
| `DELETE_SNAPSHOT` | 带 `snapshot_uri` → `deleteSnapshot`（删气泡条目）；只带原图信息 → `deleteOriginalOnly`（仅删相册） |

**`showSnapshot(uri, origPath, takenMs)` 流程**（`OverlayBubble.kt:140`）：

1. 后台线程解码校验 URI 可读（`DebugToast` 提示 `截图读取成功: 宽x高`）；
2. 若有截图时间，`SnapshotSourceResolver.resolve` 反查截图来源 App（见下）；
3. 清掉文件已不存在的失效条目（点到旧内容）；
4. **新会话判定**：若当前无可见气泡、无待触发的定时任务、且不在重建中，视为「新会话」，清空历史残留 URI；
5. 去重后 `addLast(uri)` 追加到队列尾部，`while (size > maxCount) removeFirst()`，即**新图在右、旧图在左**，超过上限淘汰最旧；
6. 重建气泡窗口：横排 `ArrayDeque` 内所有缩略图（CENTER_CROP 圆角，圆角 = 图标尺寸的 1/4），动画切走旧窗口后显示新窗口；
7. 记录 `snapshotView` / `snapshotParams` / `snapshotDismiss`（快照会话的存活三件套）；
8. `scheduleSnapshotAutoClose` 按关闭方式挂起定时或常驻（见 2.5）。

**截图来源 App**：设置页可选择两种判断方式。开启「截图来源按名称判断」后，`SnapshotSourceResolver`（`SnapshotSourceResolver.kt`）从截图文件名任意位置提取由 `.` 连接的包名片段（例如 `Screenshot_..._com.example.supermi.jpg` 提取 `com.example.supermi`），识别不到时回退到时间判断；关闭时始终使用时间判断。时间判断在 system_server 内用 `UsageStatsManager.queryEvents(takenMs - 24h, takenMs)` 扫描 `ACTIVITY_RESUMED` / `MOVE_TO_FOREGROUND` 事件，取截图时刻最近一次的前台 App 包名，再经 PackageManager 取应用名；命中时日志输出 `SuperMi: 截图来源: <App名> pkg=<packageName>`。两种方式都无法得到来源时，该图为空来源，查看框只显示页码。

**窗口参数**：`TYPE_SYSTEM_ERROR` + `FLAG_NOT_FOCUSABLE or FLAG_NOT_TOUCH_MODAL`，`gravity = TOP | CENTER_HORIZONTAL`，`layoutInDisplayCutoutMode=ALWAYS`，`setFitInsetsTypes(0)` 避开系统窗口 insets，标题 `SuperMi Snapshot`。

设置页“截图气泡”标题栏右侧的刷新按钮会检查 system_server 中的截图队列和悬浮窗口：若队列仍在但窗口丢失或未挂载，则按当前设置重建；正常已有窗口时不重复重建。system_server 重启导致队列本身丢失时，本按钮无法从磁盘恢复截图。

### 2.3 位置：与复制气泡共享设置，自动让位

- **同一套位置参数**：`x = BubblePrefs.xOffsetDp(ctx, count)`、`y = BubblePrefs.topOffsetDp(ctx, count)`，`count` 为当前张数（1/2/3）——即设置页「气泡位置」中 1/2/3 个图标的位置，截图气泡直接用对应档位。
- **让位规则**（`snapshotAvoidX`，`OverlayBubble.kt:446`）：复制气泡在场时，截图气泡水平让开，**优先右移**（`复制气泡宽/2 + 截图气泡宽/2 + 14dp`），右缘放不下则左移；复制气泡消失 `dismiss()` 时调用 `relocateSnapshot()` 恢复原位。
- **复制气泡永优先**：复制气泡 `showBubble` 成功后立即 `relocateSnapshot()`，保证临时复制任务不被截图气泡挡住；截图气泡不反推复制气泡。
- **宽度估算**：`snapshotWidthDp = n*size + (n-1)*gap + (size/3)*2`，复制气泡宽度用 `textBubbleWidthDp`（图标数同样式），两者均独立于实际测量，便于快速布局；让位判断用 `Resources.getSystem()` 屏宽与 ±中心半宽约束。

### 2.4 原图反查与删除链路

**`.orig` 伴生文件**（与缓存图同名 + `.orig` 后缀，`SnapshotStore` 维护）：

```text
path=/storage/emulated/0/Pictures/Screenshots/Screenshot_....jpg   # 相册原图
uri=content://media/external_primary/images/media/1000010xxx        # 原图 MediaStore URI
taken_ms=1788052614925      # 截图拍摄时间（毫秒），用于反查来源 App；不可用时不写
saved_path=...   # 可选：无法反查到原图时，退回「保存到相册」重建副本的位置
saved_uri=...
keep_on_close=true   # 可选：本次关闭保留原图，取消展示时不再删相册原图
```

**反查原图**（`resolveOriginalPath`）：`file://` 直接取路径；`content://` 查 MediaStore `DATA` 列，查不到再用 `RELATIVE_PATH + DISPLAY_NAME` 拼 `/storage/emulated/0/...`；均失败则记「未解析到原图路径」，之后只能删缓存、无法删相册。

**截图时间**（`resolveCaptureTime`）：优先查 MediaStore 的 `DATE_TAKEN`/`DATE_ADDED`，查不到再从系统截图文件名（如 `Screenshot_2026-08-30-09-16-51-53_xxx.jpg`）解析；结果随 `.orig` 的 `taken_ms=` 与广播传给 system_server，驱动时间判断。截图文件名同时会按设置尝试提取点号包名片段，用于名称判断。

**系统截屏目录判定**：设置页 `snapshot_dir` 手动选择的目录优先（非绝对路径忽略），未设置时按固定候选自动检测：`Pictures/Screenshots`、`DCIM/Screenshots`、`Pictures/截屏`、`DCIM/截屏`（`SnapshotStore.autoDetectScreenshotDir`）。

**可配置最近限制**：`shouldDeleteOriginal` 要求原图文件必须位于系统截屏目录内，且 `taken_ms` 距今不超过 `snapshot_delete_hours`；默认 6 小时，可选 1/3/6/12 小时。不满足时只删缓存、跳过删原图并输出日志。

**删除缓存（App 进程）**：查看框内「取消展示」→ `SnapshotStore.delete(uri)`。URI 不直接当文件路径用，而是按 `lastPathSegment` 文件名 `resolveCacheFile` 映射回 `supermi_snapshots` 目录（防路径穿越）。随后：

1. 读 `.orig`；
2. 若「自动删除相册原图」开且 `.orig` 没有 `keep_on_close=true`，先过 `shouldDeleteOriginal` 的设置目录、目标存在与可配置时限判定；
3. 把原图路径、来源 URI、文件名和时间提交给 system_server；
4. 删 `.orig` 与缓存文件。原图统一由 system_server 按「精确 MediaStore URI → 设置目录唯一媒体行 → 已验证路径 → 厂商分享缓存」顺序处理，App 不再尝试 root 或直接删除原图。

**删除相册（system_server 进程）**：App 受 scoped storage 限制删不掉相册文件时，由 system uid 兜底（`OverlayBubble.deleteOriginalBySystem`）：先按分享 URI `contentResolver.delete(uri)` + `File.delete`；对 MIUI 裸文件名再用 `name`/`takenMs` 反查 MediaStore 相册行，命中后按 `_id` 删行并删物理文件，均以系统权限执行（未反查到时日志 `system 删原图 medias 未反查到相册行`）。同时广播里的 `snapshot_uri` 会驱动气泡移除该缩略图并重建窗口。

**两种"只删相册"与"删缓存"的区分**：

| 操作 | 缓存 | 气泡 | 相册原图 |
|---|---|---|---|
| 「取消展示」 | 删 | 移除该项 | 按开关 |
| 「删除相册图片」（关闭自动删除时左侧按钮） | 保留 | 保留 | 删原图 + 删 save 副本 |
| 「保存到相册」（开启自动删除时左侧按钮） | 保留 | 保留 | 标记 `keep_on_close`，本次关闭不删原图；无原图记录才重建副本 |
| 定时关闭到期（查看框未打开） | 全删 | 消失 | 按开关 |
| 查看框打开期间到期 | 保留 | 查看框退出后显示 10 秒 | 查看框退出后仍按开关处理 |

`SnapshotStore.saveToGallery` 有原图记录时只写 `keep_on_close=true`，不再生成 `SuperMi_<缓存名>` 副本；只有 `resolveOriginalPath` 反查失败（无 `.orig`）时才退回 MediaStore `insert`（`IS_PENDING` 两段写入）重建副本。之后同一张图的「删除相册图片」仍会连历史副本一起删（`deleteGalleryOnly`）。

### 2.5 关闭方式：定时关闭 vs 一直开启

设置页 `关闭方式` 两档（`snapshot_auto_close`）：

- **一直开启**（默认）：不挂定时。气泡在**点开查看框内「取消展示」**前一直保留；`dismissSnapshot` 只负责在滚动淘汰/删除时移除旧窗口。
- **定时关闭**：`scheduleSnapshotAutoClose` 记录本次会话的绝对截止时间，到 `snapshot_ttl_secs`（15~600 秒步进预设，默认 60）后：若查看框未打开则清空队列 → 移除窗口 → 广播 `CLEAR_SNAPSHOTS` 给 App → `SnapshotCleanReceiver.deleteAll` 走完整删除链路；若查看框仍打开则只移除气泡并保留截图，查看框退出后显示气泡 10 秒再执行清理。查看框退出前未到期则继续原剩余时间，期间再次打开查看框时沿用同一截止时间。TTL 滑条仅此档生效（另一档置灰），且默认一直开启时 TTL 不生效，切到定时关闭后默认 60 秒。
- 无论哪档，新图到达、删除等都会取消旧定时重新计算。

### 2.6 查看框：从气泡位置展开的全屏查看器

**入口参数**：点击缩略图时 `OverlayBubble` 取该图的屏幕坐标 `(loc[0], loc[1], width, height)`，随 Intent 传 `EXTRA_ORIGIN_X/Y/W/H`；Activity 为透明主题（`Theme.SuperMi.Viewer`），解码完成前不播动画，避免空框放大闪烁。

**入场/退场**（`playEnter` / `finishWithExit`）：

- 入场：图片区以气泡原点为中心等比缩小摆放（缩放比例 = 气泡尺寸/区域尺寸，位移 = 中心差），`ValueAnimator` 340ms 缓出放大至全屏；正常档使用黑底背景。模糊档以透明窗口为基础，给窗口加 `FLAG_BLUR_BEHIND`，`blurBehindRadius` 为 48dp 并跟随动画渐变，同时只叠加约 10% 的白色透明雾面，不再绘制灰黑渐变、主色光晕、高光或细砂；设备不支持跨窗口模糊时系统静默忽略模糊，保留白色透明层作为降级效果。顶部状态栏不被雾面覆盖，底部后景模糊连续到导航栏区域；底部按钮栏自身通过底部 padding 延伸到系统手势条区域。底部栏在进度 0.35 后淡入上移。
- 退场：反向 280ms（无原点时 200ms）加速缩回气泡位置、背景/模糊半径淡回初始，动画结束后 `finish()` + `overridePendingTransition(0,0)`（即不残留系统转场）。触发方式：**上滑**（未放大状态）、**系统返回键**、关闭最后一张图。
- 无气泡触点（extras 缺失）时退化为纯淡入淡出。

**系统栏避让**：透明窗口使用 `setDecorFitsSystemWindows(false)`；状态栏保持透明且不被白色雾面覆盖，模糊档使用深色状态栏图标以适配浅色底层页面，普通黑底档使用浅色图标。`applySystemBarInsets` 通过 `ViewCompat.setOnApplyWindowInsetsListener` 将 `systemBars` 的 top 应用于 `root`，bottom 仅用于底部按钮栏 padding；背景模糊层只避开顶部状态栏，不避开底部导航栏，以保证小白条区域也有相同的后景模糊。insets 为 0（部分 MIUI 透明窗口首次不派发）时回落 `systemDimen("status_bar_height")` / `navigation_bar_height`，`root.post` 再兜底补一次。

**交互**（`ZoomableImageView` + 双层页）：

| 手势/操作 | 行为 |
|---|---|
| 左右快速滑动（未放大） | 切换图片，左滑看右一张（新图）、右滑看左一张（旧图），不循环；双层视图联动滑动：新图滑入、旧图被同步推走，避免切换闪黑 |
| 双击 / 双指缩放 / 拖动 | 放大、平移、还原；初始 8dp 边距在缩放后取消，图片可铺满左右；放大状态下不触发翻页/上滑退出 |
| 单击图片 | 切换底部操作栏显隐（隐藏时 `INVISIBLE`） |
| 上滑（未放大） | 退场返回原界面 |
| 按 Home 返回主页 | 先发送恢复气泡广播，再结束查看框；从页码区启动来源 App 时不触发该逻辑 |
| 底部「取消展示」 | 删除当前图缓存并切邻图；多图时按剩余张数重建页码（`x/y`），剩最后一张时点它=退场 |
| 右下角页码区 | 显示当前张来源 App 图标；多图时图标后附「N/M」页码，来源为空只显示页码；长按可看来源应用名，点击可拉起对应 App |
| 左侧按钮 | 自动删原图开 →「保存到相册」；关 →「删除相册图片」（临时改主意） |

**图片加载**：按屏幕尺寸降采样（`inSampleSize` 2 的幂）解码，大图不爆内存；最近 3 张内存 LRU 缓存并预加载左右相邻图，滑动切换可直接命中缓存（动画 120ms），加载失败显示居中「图片无法读取」并同样播放入场。

**点击来源 App 返回**：设置页「来源返回后」控制；默认**关闭查看框**（从来源 App 返回时查看框直接结束，露出打开查看框前的界面），也可选**回到查看框**。

**点击气泡行为**：设置页「点击气泡后」默认**展开查看框**；选择**打开来源 App**时，截图气泡改显示对应来源 App 图标，并直接启动当前截图识别到的来源应用。该设置实时刷新当前气泡；长按截图气泡（无论显示截图还是 App 图标）都会删除其绑定的截图并关闭当前复制气泡，不进入查看框。来源识别为空、应用没有启动入口或启动失败时，显示截图缩略图并回退到展开查看框。

## 三、设置项与默认值

设置页入口：**截图气泡**（副标题「分享截图到本App后显示缩略气泡」）。

| 设置 | 键（AppConfig/Settings.System） | 默认 | 说明 |
|---|---|---|---|
| 最多显示张数 | `snapshot_max_count` | 1（1~3） | **上限**而非必须张数；新图在右，超限淘汰最左（最旧） |
| 关闭方式 | `snapshot_auto_close` | 一直开启 | 一直开启 / 定时关闭（TTL 60 秒） |
| 气泡停留时间 | `snapshot_ttl_secs` | 60 | 预设 15/30/60/120/180/300/600 秒，仅定时关闭档可用 |
| 自动删除相册原图 | `snapshot_auto_clean` | 开 | 只针对系统截屏目录内、分享后仍在删除时限内的最近截图；关闭则相册原图保留 |

| 自动删除时限 | `snapshot_delete_hours` | 6 小时 | 「查看更多」中的高级项；1/3/6/12 小时，位于截图来源设置下方 |
| 系统截屏目录 | `snapshot_dir` | 未设置 | 点击直接唤起系统目录选择器（SAF tree URI 转物理路径）；删除原图优先在该目录内定位，未设置时自动检测常见截图目录 |
| 来源返回后 | `snapshot_open_source_close` | 关闭查看框 | 从点击的来源 App 返回后直接关闭查看框 / 回到查看框 |
| 点击气泡后 | `snapshot_click_open_source` | 展开查看框 | 展开截图查看框 / 显示来源 App 图标并直接打开已识别的来源 App；来源未知或无法启动时显示截图并回退到查看框 |
| 查看框背景 | `snapshot_bg_blur` | 普通 | 普通黑底 / 白色透明模糊（Android 12+ 跨窗口模糊，设备不支持时退化为白色透明层） |
| 气泡底色/边框条 | `bg_light` / `bg_border` | 黑底、不显示 | 与复制气泡共用：`bg_light` 选黑/白，`bg_border` 选是否显示 1dp 描边；黑底黑边、白底用 `#66FFFFFF` 毛玻璃白边 |

配置链路沿用全局模型：App 写 `files/supermi_config` + `Settings.System` → `BubblePosProvider` 内存变量 → system_server 内 `BubblePrefs` 读 Provider（无 Provider 时回落 Settings.System 兜底）。

截图气泡配置同时纳入主页的导入/导出：`snapshot_max_count`、`snapshot_ttl_secs`、`snapshot_auto_clean`、`snapshot_source_by_name`、`snapshot_delete_hours`、`snapshot_auto_close`、`snapshot_open_source_close`、`snapshot_click_open_source`、`snapshot_bg_blur`、`snapshot_corner_dp` 与 `snapshot_dir` 均按 `key=value` 写入 `supermi_config`。导入后由 `MainActivity.recreate()` 重新加载并同步 `BubblePosProvider`，system_server 侧下一次读取即可使用新设置。

## 五、常踩的坑 / 改动须知

- **改气泡侧代码必须重启系统**：`OverlayBubble`/`HookEntry` 运行在 system_server，重装 APK 后需要 LSPosed 重新加载模块（重启系统）才生效；`ShareReceiverActivity`/`SnapshotViewerActivity`/`SnapshotStore` 是 App 侧，普通安装即可。
- **分享 Intent 读不到截图来源**：`ACTION_SEND` 只携带图片 URI，来源 App 由「App 记下截图拍摄时间 → system_server 查 UsageStats」两条链路拼出来；若 MediaStore 没有拍摄时间且文件名不是系统截图格式，来源会为空或近似。
- **磁盘与气泡数量必须同步调**：`SnapshotStore.cleanup` 的 `keep` 来自设置的最大张数；气泡侧 `snapshotMaxCount` 控制 `ArrayDeque` 长度。两者不同步会出现「没触发新会话却显示残留图」。
- **URI 与路径不要混用**：删除缓存一律按文件名重映射到缓存目录（`resolveCacheFile`），不要信任外部传入的 path；相册原图删除一律走 system_server，App 进程的 `File.delete` 按 scoped storage 随时可能失败，属预期。
- **「自动删除相册原图」不是无条件删**：App 先判定原图位于系统截屏目录内、目标文件存在，且拍摄时间没有超过设置的 1/3/6/12 小时时限才允许删；默认 6 小时。相册分享来的其他目录图片和超时截图只会删 App 缓存。
- **查看框避让不要改回 `setDecorFitsSystemWindows(true)`**：透明窗口已由 `applySystemBarInsets` 手动按系统栏 padding 避让；改回 true 会叠加系统自动避让，普通机型在状态栏下多出一条空白，MIUI 机型则因不派发 insets 反而无效果。
- **Home 返回必须走恢复链路**：用户按 Home 时查看器可能只收到 `onUserLeaveHint` / `onStop`，不一定触发 `onDestroy`；`SnapshotViewerActivity` 需要先发送带权限的 `RESTORE_SNAPSHOT` 广播，再结束查看器，否则 `OverlayBubble` 会持续认为查看器仍在占用而不显示气泡。打开来源 App 时用独立标记区分，不能误触发 Home 恢复。
- **「定时关闭」也依赖 App 存活**：广播 `CLEAR_SNAPSHOTS` 需要拉起 App 进程；若广播失败，缓存会留到下次 `save`/`cleanup` 被回收。
- **新会话判定**：气泡在场时新截图追加不重置；气泡已消失（未点开、未定时）后再来图视为新会话、丢弃残留。若想增加「会话合并窗口」等策略，改点在 `showSnapshot` 的判定与 `snapshotDismiss` 生命周期。

## 六、Android 16 不显示气泡：根因与修复记录

### 6.1 现象

在 Android 16（小米 HyperOS）上，从其他 App 截图并分享后，截图文件已经成功写入：

```text
/data/user/0/com.example.supermi/no_backup/supermi_snapshots/
```

但悬浮气泡不出现；系统界面截图有时正常，普通 App 中更容易复现。修改「最多显示张数」或背景色后，问题也可能再次出现。

### 6.2 定位结论

原始实现（提交 `ba673b35`）的主要结构已经正确：

1. `ShareReceiverActivity` 在 App 进程异步保存图片；
2. 保存后发送 `SHOW_SNAPSHOT` 到 `android` 包；
3. system_server 中的 `HookEntry` 动态接收器调用 `OverlayBubble.showSnapshot`；
4. `OverlayBubble` 解码图片并创建 `TYPE_SYSTEM_ERROR` 窗口。

但当时存在两个 Android 16 兼容问题：

- **URI 授权生命周期过短**：`BroadcastReceiver.onReceive()` 直接把任务丢给后台线程后立即返回。Android 16/部分 HyperOS 会在返回后撤销临时 URI grant，system_server 后台线程再读取 FileProvider URI 时就可能失败。
- **查看器状态可能残留**：查看器打开时通过 `snapshotViewerOpen` 暂停重建气泡。如果返回广播因权限不匹配或进程/转场异常没有送达，状态会永久保持 `true`，后续截图虽然保存和广播成功，却被逻辑主动跳过。

ADB 曾确认广播本身已经送达：

```text
SHOW_SNAPSHOT ... DELIVERED ... ReceiverList ... system/1000
```

因此问题不是分享入口，也不是截图文件夹写入失败，而是 system_server 读取/状态门控阶段。

### 6.3 实际修复

#### A. 使用 `goAsync()` 保持 URI 授权

`HookEntry` 的 `SHOW_SNAPSHOT` 接收器现在先调用 `goAsync()`，将 `PendingResult` 传给 `OverlayBubble.showSnapshot`。图片 URI 解码、队列更新完成后，在 `finally` 中调用 `pending.finish()`；异常路径也保证调用 `finish()`。

这样临时授权覆盖整个异步读取窗口，不会因为 `onReceive()` 提前返回而失效。事件同时携带缓存绝对路径 `snapshot_cache_path` 作为读取兜底，并在发送端通过 `ClipData` 和 `grantUriPermission("android", ...)` 传递读取权限。

#### B. 修正查看器恢复广播权限

`SnapshotViewerActivity` 退出时发送 `RESTORE_SNAPSHOT` 时，补上：

```kotlin
sendBroadcast(intent.setPackage("android"),
    "com.example.supermi.permission.SHOW_SNAPSHOT")
```

否则 system_server 中声明了 required permission 的动态接收器可能收不到恢复事件。

#### C. 清理陈旧查看器状态

记录查看器打开时间 `snapshotViewerOpenedAt`。如果后续新截图到达时发现：

- `snapshotViewerOpen == true`；
- 实际没有 `snapshotView`；
- 状态持续超过 2 秒；

则自动清除陈旧状态，再正常显示新气泡。这是 Android 16 转场/进程异常时的保险措施，不影响正常查看器流程。

#### D. 保留 Android 16 查看器布局修复

查看器继续使用 AndroidX 返回分发器、`setDecorFitsSystemWindows(false)` 和手动 WindowInsets 处理；入场动画和退场动画互斥，避免预测性返回动画与自定义动画同时修改 `alpha/scale`。这些改动不是本次“气泡不显示”的根因，不应回滚。

### 6.4 验证方法

安装 APK 后，App 进程改动可立即生效；`HookEntry`/`OverlayBubble` 在 system_server 中运行，必须通过 LSPosed「重启系统框架/热重启」加载新代码（不要求整机重启）。

分享一次截图后，关键日志应为：

```text
SuperMi: snapshot event received ...
SuperMi snapshot main state viewer=false ...
SuperMi snapshot bubble added ...
```

其中 `viewer=true` 且 `snapshot bubble deferred while viewer is open` 表示查看器状态仍未恢复；`snapshot URI read failed`/`snapshot cache path read failed` 表示授权或 Provider 读取仍有问题；`snapshot bubble add failed` 表示窗口层级或权限问题。

### 6.5 关于设置项变更

`最多显示张数`、背景色/透明度只通过 `BubblePrefs` 重新读取配置并影响新窗口样式，不会直接关闭截图功能。若变更设置后不显示，应优先检查 `snapshot main state` 日志和是否发生 `snapshot bubble deferred`，不要先怀疑 edge-to-edge 修复。
