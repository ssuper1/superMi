# 复制Mi达 —— 配置导入导出说明

> 面向后续开发者/协作者：描述「导入/导出配置」功能的实现方式、文件格式、涉及的字段与边界情况。

---

## 一、功能概述

- **入口**：主页「其他」板块，`row_export`（导出配置）、`row_import`（导入配置）。
- **导出**：把当前全部配置写入一个 `.txt` 文本文件，由系统文件选择器（SAF）决定保存位置。
- **导入**：从用户选中的备份文件读取 `key=value`，整体覆盖本地配置并刷新界面。
- **本质**：配置的唯一持久化载体是 `files/supermi_config`（key=value 文本），导入导出就是这份文件的「拷出/拷回」。

---

## 二、UI 入口

布局 `res/layout/activity_main.xml`，「其他」板块下新增一张卡片，含两行：

| View id | 标题 | 副标题 | 图标 |
|---|---|---|---|
| `row_export` | 导出配置 | 备份当前全部设置到文件 | `ic_public` |
| `row_import` | 导入配置 | 从备份文件恢复设置 | `ic_extension` |

点击监听（`MainActivity.onCreate`）：

```kotlin
findViewById<View>(R.id.row_export).setOnClickListener { exportConfig() }
findViewById<View>(R.id.row_import).setOnClickListener {
    importLauncher.launch(arrayOf("text/plain", "application/octet-stream"))
}
```

## 三、导出实现

### 3.1 流程

1. `exportConfig()` 先调用 `saveConfig()`，把内存中的当前字段（位置/间距/图标大小/背景透明度等）同步落盘到 `files/supermi_config`，保证导出的是最新值。
2. 通过 `ActivityResultContracts.CreateDocument("text/plain")` 打开系统「新建文件」对话框，文件名建议为 `supermi_config_backup.txt`。
3. 用户在保存回调里拿到 `Uri` 后，`writeExport(uri)` 读取 `AppConfig.read(this)`（即整份配置文件），按 `key=value` 逐行拼接，通过 `contentResolver.openOutputStream(uri)` 写入。

### 3.2 关键代码

```kotlin
private val exportLauncher = registerForActivityResult(
    ActivityResultContracts.CreateDocument("text/plain")
) { uri ->
    if (uri != null) {
        val ok = writeExport(uri)
        Toast.makeText(this, if (ok) "已导出配置" else "导出失败", Toast.LENGTH_SHORT).show()
    }
}

private fun exportConfig() {
    saveConfig()
    exportLauncher.launch("supermi_config_backup.txt")
}

private fun writeExport(uri: Uri): Boolean {
    return try {
        val content = AppConfig.read(this).entries.joinToString("\n") { "${it.key}=${it.value}" } + "\n"
        contentResolver.openOutputStream(uri)?.use { os ->
            os.write(content.toByteArray(Charsets.UTF_8))
        } != null
    } catch (_: Throwable) {
        false
    }
}
```

> 说明：导出内容与 `files/supermi_config` 完全一致，因此备份文件可直接回灌，也可跨设备迁移（不含设备特定信息，仅包名与参数）。

## 四、导入实现

### 4.1 流程

1. `ActivityResultContracts.OpenDocument()` 打开文件选择器，`MIME` 限定 `text/plain`、`application/octet-stream`。
2. `importConfig(uri)` 读取文本：
   - 逐行解析 `key=value`（`indexOf('=')` 取首个 `=`，key/value 两侧 `trim`）。
   - 忽略不含 `=` 的行（可容忍注释头、空行）。
3. 若解析结果为空 → Toast「文件为空或格式不正确」，**不覆盖**现有配置。
4. 非空 → `AppConfig.write(this, imported)` 整体覆盖文件 → Toast「导入成功」→ `recreate()` 重建整个界面。
5. 任何异常 → Toast「导入失败」，不改变现有配置。

### 4.2 关键代码

```kotlin
private val importLauncher = registerForActivityResult(
    ActivityResultContracts.OpenDocument()
) { uri ->
    if (uri != null) importConfig(uri)
}

private fun importConfig(uri: Uri) {
    try {
        val text = contentResolver.openInputStream(uri)?.bufferedReader()?.use { it.readText() }
            ?: throw IllegalStateException("无法读取文件")
        val imported = mutableMapOf<String, String>()
        for (line in text.lines()) {
            val i = line.indexOf('=')
            if (i > 0) imported[line.substring(0, i).trim()] = line.substring(i + 1).trim()
        }
        if (imported.isEmpty()) {
            Toast.makeText(this, "文件为空或格式不正确", Toast.LENGTH_SHORT).show()
            return
        }
        AppConfig.write(this, imported)
        Toast.makeText(this, "导入成功", Toast.LENGTH_SHORT).show()
        recreate()
    } catch (_: Throwable) {
        Toast.makeText(this, "导入失败", Toast.LENGTH_SHORT).show()
    }
}
```

### 4.3 导入后的界面刷新

导入不走「逐控件回写」，而是 `recreate()` 整页重建：Activity 销毁重建后 `onCreate` 里的 `loadConfig()` 会重新从配置文件读取全部字段，并用 `setupIconSeekBar` / `setupBgAlphaSeekBar` / `setupDismissSeekBar` / `updateGapUI` / `updateMaxLenSeg` 等把**所有控件**（含 `seek_bg_alpha` / `tv_bg_alpha` 背景透明度栏、`seek_dismiss` / `tv_dismiss` 消失时间栏）按导入值重新初始化。

> 用 `recreate()` 而非逐字段 `refreshUiFromConfig()` 的原因：新增字段时不会漏刷新任何控件，从根上避免「某字段导入生效但对应控件仍是旧值」这类问题。

> 注意：导入后字段经 `loadConfig()` 落入内存，并 `syncProvider()` 同步给 `BubblePosProvider` 静态变量，使 system_server 侧（真实气泡）也能读到新值。

## 五、文件格式

- 纯文本，UTF-8，每行一条 `key=value`，行尾 `\n`。
- 与内部配置文件 `files/supermi_config` 完全同构，因此两者可互相拷贝。
- 导入解析器忽略不含 `=` 的行，所以备份文件头部可附加 `#` 注释而不影响导入。

示例：

```text
x1=0
y1=30
x2=0
y2=35
x3=110
y3=30
addr_app=
url_app=
phone_app=
debug=0
max_len=400
preview_icons=3
gap12_2=31
gap12_3=6
gap23_3=39
icon_size=24
bg_alpha=20
bg_light=0
bg_border=0
dismiss_secs=5
platform_rules=[{"kw":"【淘宝】",...}]
number_rules=[{"prefix":"1","lengths":[11],"apps":[]}]

snapshot_delete_hours=6
snapshot_auto_close=0
snapshot_open_source_close=1

snapshot_dir=
```

## 六、涉及的配置字段

导出的内容即整份 `AppConfig` 配置，包含（但不限于）：

| key | 含义 |
|---|---|
| `x1/y1` ~ `x3/y3` | 1/2/3 个图标时的气泡偏移 |
| `addr_app` / `url_app` / `phone_app` | 地图/浏览器/拨号 App（逗号多选） |
| `debug` | 调试开关（0/1） |
| `max_len` | 识别长度上限 |
| `preview_icons` | 预览图标个数（1~3） |
| `gap12_2` / `gap12_3` / `gap23_3` | 图标间距 |
| `icon_size` | 图标大小 |
| `bg_alpha` | 背景透明度（0~100，默认 20） |
| `bg_light` | 背景黑/白（0=黑，1=白，默认 0） |
| `bg_border` | 边框条（0=不显示，1=显示黑边/白玻璃边，默认 0） |
| `dismiss_secs` | 气泡自动消失秒数（1~10，默认 5） |
| `platform_rules` | 平台规则 JSON |
| `number_rules` | 号码规则 JSON |
| `history` | App 选择器的最近选择记录 |
| `snapshot_max_count` | 截图气泡最多显示张数（1~3） |
| `snapshot_ttl_secs` | 截图气泡定时关闭秒数（15~600） |
| `snapshot_auto_clean` | 关闭展示时是否自动删除截屏原图（0/1） |
| `snapshot_source_by_name` | 是否优先按截图文件名判断来源 App（0/1） |
| `snapshot_delete_hours` | 自动删除原图的时间限制（1/3/6/12 小时） |
| `snapshot_auto_close` | 截图气泡是否定时自动关闭（0/1） |
| `snapshot_open_source_close` | 从来源 App 返回后是否关闭查看框（0/1） |
| `snapshot_bg_blur` | 查看框是否使用透明模糊背景（0/1） |
| `snapshot_corner_dp` | 截图缩略图圆角大小（0~40dp） |
| `snapshot_dir` | 手动指定的系统截屏目录，空值表示自动检测 |

**背景透明度（`bg_alpha`）在导入导出中的适配点**：

- 写入：`saveConfig()` 里 `m[BubblePosProvider.KEY_BG_ALPHA] = "$bgAlpha"`，故导出文件必然包含 `bg_alpha`。
- 读取：`loadFieldsFromSettings()` 里 `bgAlpha = m[KEY_BG_ALPHA]?.toIntOrNull()?.coerceIn(0,100) ?: fromSettings("bg_alpha", bgAlpha)`。
- 同步：`syncProvider()` 里 `BubblePosProvider.bgAlpha = bgAlpha`。
- 刷新：导入后 `recreate()` 重建界面，`onCreate` 里 `setupBgAlphaSeekBar` 按 `bgAlpha` 初始化 `seek_bg_alpha` / `tv_bg_alpha`。

**消失时间（`dismiss_secs`）在导入导出中的适配点**：

- 写入：`saveConfig()` 里 `m[BubblePosProvider.KEY_DISMISS_SECS] = "$dismissSecs"`，故导出文件必然包含 `dismiss_secs`。
- 读取：`loadFieldsFromSettings()` 里 `dismissSecs = m[KEY_DISMISS_SECS]?.toIntOrNull()?.coerceIn(1,10) ?: fromSettings("dismiss_secs", dismissSecs)`。
- 同步：`syncProvider()` 里 `BubblePosProvider.dismissSecs = dismissSecs`；system_server 侧 `OverlayBubble` 通过 `BubblePrefs.dismissMs(ctx)` 取实际毫秒数做自动消失。
- 刷新：导入后 `recreate()` 重建界面，`onCreate` 里 `setupDismissSeekBar` 按 `dismissSecs` 初始化 `seek_dismiss` / `tv_dismiss`（显示 `${v}s`，进度 = 秒数-1）。

## 七、边界与注意事项

1. **导出前先 `saveConfig()`**：确保内存里尚未落盘的改动被带上，避免导出到旧值。
2. **导入是整体覆盖**：`AppConfig.write` 会清掉原文件再写新内容；导入的备份文件应包含完整字段（本功能导出的文件天然完整）。
3. **解析只认 `key=value`**：`=` 出现在 value 里也不会截断（`indexOf('=')` 取首个 `=` 后，value 保留其余部分）。JSON 值一般不包含 `=`，无影响。
4. **空/坏文件不覆盖**：解析结果为空或读取异常时直接返回，保护现有配置。
5. **导入后靠 `recreate()` 重建**：仅写文件不够，`recreate()` 触发 `onCreate → loadConfig() → syncProvider()`，既刷新全部控件，也把各字段（含截图气泡的 `snapshot_*` 设置）同步给 Provider 静态变量，使 system_server 侧真实气泡读到新值。
6. **SAF 无额外权限**：导入导出走 `CreateDocument`/`OpenDocument`，使用系统文件选择器授权，无需 `READ/WRITE_EXTERNAL_STORAGE` 权限。
