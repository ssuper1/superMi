# 复制Mi达 —— 项目逻辑说明

> 面向后续开发者/协作者的逻辑说明。本文描述「做了什么、怎么工作、关键参数在哪、改哪里」。
> 总-分结构：先总览全局，再逐功能拆解。

---

## 一、项目总览

**定位**：Android LSPosed 模块（应用名「复制Mi达」，包名 `com.example.supermi`）。

**核心原理**：监听全局复制操作 → 对复制内容做类型识别（网址/地址/手机号/快递单/平台口令）→ 屏幕弹出悬浮气泡显示可打开的 App → 点击跳转对应 App。

**运行环境**：
- 必须 root + Magisk + Zygisk + LSPosed（模块在 **system_server** 进程内运行，全局生效）
- LSPosed 作用域：勾选「系统框架」（System Framework）
- 模块 manifest 里 `xposedscope=android` 使其在作用域界面推荐置顶
- minSdk 31（Android 12）、targetSdk 36（Android 16）；LSPosed 框架本身支持 8.1~17

**为什么用 LSPosed**：Android 10+ 后台 app 无法读剪贴板，普通方案不可行；LSPosed 直接 hook system_server 的 `ClipboardService`，绕过限制。

---

## 二、整体工作链路（总）

```
用户复制
   ↓
[HookEntry]  hook ClipboardService.setPrimaryClip（ColorOS 上是 setPrimaryClipInternal）
   ↓
[ContentClassifier.classifyAll(ctx, text)]
   ├─ 长度上限 maxLen 检查
   ├─ 平台识别（PlatformRuleStore.match）→ 得到 platformApps
   ├─ URL 识别 → Recognized(URL)
   ├─ 号码识别（NumberRuleStore.match / 手机号）→ Recognized(PHONE)
   └─ 地址识别（AddressMatcher.analyze）→ Recognized(ADDRESS)
   ↓
[OverlayBubble.show]  逐个类型 resolveTargets（解析可打开的 App，最多 3 个）
   ↓
悬浮气泡（TYPE_SYSTEM_ERROR 系统窗口，位于状态栏之上）
   ↓
点击图标 → [OverlayBubble.launch]  深链 或 启动 App
```

**关键点**：
- 识别出几个类型就并排几个图标，总上限 3 个
- 气泡 6 秒自动消失；3 秒内同一文本去重
- 配置通过 ContentProvider 从 App 侧同步给 system_server，并在 Settings.System 持久化兜底

## 四、功能细节（分）

### 4.1 剪贴板监听（HookEntry）
- 只在 `lpparam.packageName == "android"`（system_server）时执行
- hook `com.android.server.clipboard.ClipboardService` 中所有名为 `setPrimaryClip` 的重载（**签名跨 ROM 不同**；ColorOS 上没有标准 `setPrimaryClip(ClipData,String,int,int)`，实际是 `setPrimaryClipInternal(ClipData,int)` 等，故按「首参为 ClipData 的方法名」匹配）
- 回调在 binder 线程，取 `args[0]` 的 ClipData 文本 → `OverlayBubble.show`

### 4.2 内容分类（ContentClassifier）
- 入参整个文本，先做 `trim`；超过 `maxLen`（默认 200）直接放弃
- **URL**：正则 `https?://[^\s"'<>]+|www\.[^\s"'<>]+`（吃到空格/引号/尖括号为止）
- **平台**：`PlatformRuleStore.match`；若命中且文本含 URL → URL 类型携带平台 apps；若命中但无 URL（纯口令文本）→ PLATFORM 类型（启动器打开）
- **号码**：先 `NumberRuleStore.match`；无命中再 fallback 手机号 `1[3-9]\d{9}`
- **地址**：平台命中时不再判地址；候选含中文才跑 `AddressMatcher`
- `Recognized(type, query, customApps, deepLink)` 为统一产出

### 4.3 地址识别（AddressMatcher + AdminTree）
**行政区划树**（`AdminTree`，数据 `assets/admin_tree.json`）
- 31 省级 / 387 市级 / 3008 区县级；名称去行政后缀（省市区县等）做匹配名，含别名（内蒙古/新疆等）
- **匹配名长度 ≥2**（过滤"文县→文"这类单字虚匹配）
- `findChain`：在文本里找最长的「父子紧邻链」，支持市级市嵌套（郑州市→巩义市→xx区），空格可跳过

**识别分档**（`AddressMatcher.analyze`，返回 isAddress/type/confidence/query/reason）
| 档 | 条件 | 结果 |
|---|---|---|
| 强 | 行政区链 ≥2（含道路/门牌/POI 更好） | 地址（confidence 0.95） |
| 强 | 道路 + 门牌号（如 文化路88号） | 地址（0.9） |
| 中 | 单个行政区 + 道路/门牌/POI | 地址（0.8~0.85） |
| 拒绝 | 数量表达反例（`九县七区`/`下辖\d+个区`，`COUNT_RE`）且无强链 | 非地址 |
| 拒绝 | 只有单个行政区 / 单个道路 / 单个 POI | 非地址 |

- **反例**：`COUNT_RE` 匹配数量表达（九县七区、下辖 X 个区等）
- **动词过滤**：道路/POI 名含动词代词（`我你他她它去在往从这那来下走跑…`）则不算
- **query 提取**：取所有命中实体（行政区/道路/门牌/POI）覆盖的最短子串

### 4.4 平台识别（PlatformRuleStore）
**规则结构** `PlatformRule(keyword, links[], app, apps[], deepLink)`
- `keyword`：带 `【】`/`「」` 的模糊匹配；不带括号 → `contains` 全文任意匹配（宽松，易误报，UI 已红色提醒）
  - `【王者荣耀】` → 正则 `【王者荣耀[^】]*】`，可匹配 `【王者荣耀送XX皮肤】`
  - `「百度网盘APP 即可获取」` → 正则 `「百度网盘APP 即可获取[^」]*」`
- `links`：`text.contains(link)` 连续子串匹配（`e.tb.cn` 与 `m.tb.cn` 不会互相误判）
- `app`：主平台 App（apps 为空时用）；`apps`：最多 3 个，为空时回退只显示 `app`
- `deepLink`：true=点击走深链（失败回退启动 App）；false=仅启动 App（由 App 用剪贴板口令识别）
- **抖音深链决策**：目前对抖音**全部内容都用深链**（保留视频一键直达）。代价：团购等场景分享短链被抖音解析成视频页而非其自身搜索，已知限制未处理
- **匹配顺序**：按规则顺序先关键字，再链接
- **缓存**：`rules(ctx)` 按 JSON 字符串缓存

**默认规则**（见文末表）

### 4.5 号码识别（NumberRuleStore）
**规则结构** `NumberRule(prefixes[], lengths[], apps[])`
- `prefixes`：开头，可逗号多值（`YT,EMS`）；可为空（任意开头）
- `lengths`：固定总长列表（`7,8,9`=7~9位；`7,9`=7或9位）；**为空时用「默认长度」范围**（11~18，可改）
- `apps`：最多 3 个；为空且是手机号 → 拨号（tel:）
- **正则**：`(?<![0-9A-Za-z])(前缀(\d{n}|...)|...)(?![0-9])`，边界防部分匹配
- **默认规则**：手机号(1,11)、YT(15位→菜鸟)、EMS(→菜鸟)、JD(→菜鸟+京东)

### 4.6 气泡渲染与跳转（OverlayBubble）
- 窗口类型 `TYPE_SYSTEM_ERROR`（系统级，位于状态栏之上），`TOP|CENTER_HORIZONTAL`，`layoutInDisplayCutoutMode=ALWAYS` + `fitInsetsTypes=0`（可到屏幕最顶/状态栏区域）
- **位置按图标个数独立**：1 个图标 → `y1/x1`，2 个 → `y2/x2`，3 个 → `y3/x3`（旧单组 `y/x` 自动迁移为三组同值）。预览区切 1/2/3 时 dpad 调的是对应个数那组
- **间距按图标个数独立**：2 个图标用 `gap12_2`；3 个图标用 `gap12_3`（1↔2）+ `gap23_3`（2↔3）；1 个图标无间距（UI 中对应滑条置灰不可操作）。`gap12/gap23` 旧键自动迁移为三组新键
- **尺寸**：图标大小 `icon_size`（16~48dp，默认 24）；内边距 `pad = iconSize/3 与 /6`；圆角 `corner = iconSize*2/3`（背景 WRAP_CONTENT 自动随图标缩放）
- **背景透明度**：`bg_alpha`（0~100%，默认 85，全局不分图标个数），作用于气泡/预览深色背景 `#3C3C3C` 的 alpha 通道
- 图标最多 3 个；图标圆角 `iconSize/4`
- **目标解析**：按类型取 apps（平台/号码的自定义 apps 或浏览器/地图默认）；自定义 apps 非空则直接按包名；为空则 `queryIntentActivities` 系统解析（自动模式）
- **跳转**：`openLauncher=false`（深链）→ 先 `ACTION_VIEW` 指定包名，失败回退启动 App 本身；`openLauncher=true` → 直接启动 App
- 去重：3 秒内相同文本忽略；后台线程处理，主线程加窗
- **解析缓存**：16 条、TTL 30 秒；**缓存 key 必须用完整 query**（曾按 host/空 key 缓存，导致 30 秒内第二次复制同 host 的 URL 复用了旧 URL，表现为"打开上一个视频"）

### 4.7 配置系统（BubblePrefs + BubblePosProvider + AppConfig）
**数据流**：
```
App 设置界面修改 → saveConfig() → 写 files/supermi_config（key=value）
   ↓（App 进程内）
BubblePosProvider（ContentProvider）从文件加载进内存
   ↓（system_server 查询，Binder.clearCallingIdentity 解决调用者身份问题）
BubblePrefs.config() → 3 秒缓存 → 成功后 persistSettings() 写入 Settings.System
   ↓（Provider 查询失败时，如 app 未启动/被停/锁屏）
回退读 Settings.System（持久化兜底）
```

**为什么两套存储**：App 读配置文件；system_server 因 SELinux 读不了 app 数据文件，故用 Provider 中转，并持久化到 Settings.System（锁屏/未启动时也能读）。

**配置自愈**：`MainActivity.loadConfig` 每个字段按「配置文件 → Settings.System → 代码默认值」取，配置文件缺失/被清时自动从 Settings 恢复，打开一次 app 即重建配置，避免数据丢失后 UI 归零。

### 4.8 配置导入导出（MainActivity）
- 入口在主页「其他」板块：`row_export`（导出）、`row_import`（导入）。
- **导出**：`exportConfig()` 先 `saveConfig()` 落盘，再用 `ActivityResultContracts.CreateDocument("text/plain")` 让用户选择保存位置，把 `AppConfig.read()` 的 key=value 原文写入（与 `files/supermi_config` 同格式，可直接回灌）。
- **导入**：`ActivityResultContracts.OpenDocument` 选文件 → `importConfig(uri)` 读文本 → 按 `key=value` 逐行解析（忽略不含 `=` 的行，含注释头亦可）→ `AppConfig.write` 整体覆盖 → `recreate()` 重建界面（`onCreate` 里 `loadConfig()` 重新读配置并初始化全部控件，含背景透明度滑条）。
- 备份文件即配置原文，跨设备可迁移；导入空文件/格式错误会 Toast 提示且不覆盖现有配置。

## 七、改动时注意的坑（重要）

1. **剪贴板 hook 签名随 ROM 变化**：标准 AOSP 是 `setPrimaryClip(ClipData,String,int,int)`；ColorOS 是 `setPrimaryClipInternal(ClipData,int)` 等。Hook 要按「首参 ClipData + 方法名含 setPrimaryClip」兼容，别写死签名。
2. **system_server 读配置**：直接读 app 数据文件会被 SELinux 拦（EACCES），必须走 ContentProvider；Provider 查询在剪贴板 hook 的 binder 线程会带调用方 uid，必须 `Binder.clearCallingIdentity()`，否则 SecurityException → 回退默认值（表现为"重启后不跟随设置"）。
3. **锁屏（CE 加密）**：设备锁屏时 app 数据目录不可访问，配置文件读写会失败；模块靠 Settings.System 兜底。改配置时注意设备是否解锁。
4. **配置属主 uid**：app 重装后 uid 可能变化，root `cp` 配置文件必须 `chown` 到当前 app uid，否则 app 读不到（表现为显示默认值）。**`./gradlew installDebug` 偶发连数据目录一起清掉**，属安装异常，需重新触发 app 启动重建。
5. **深链不是万能**：只有注册了域名 App Link 的 app（拼多多/淘宝/抖音/B站/酷安）能深链跳详情；其余（闲鱼/百度网盘/小红书/移动云盘）要关深链、仅启动 App 靠剪贴板口令。
6. **悬浮窗在状态栏上层**：`TYPE_SYSTEM_ERROR` 才能覆盖状态栏；普通 `TYPE_APPLICATION_OVERLAY` 永远在状态栏下方。
7. **LSPosed 模块**：改 manifest/`xposed_init` 后需重装并在 LSPosed 启用作用域「系统框架」；system_server 的模块代码改动需重启才生效（App 侧改动只需重装）。**更新模块用 `./gradlew installDebug`**（`adb install` 非标准安装会触发 LSPosed 弹"部署优化"提示），装完同步 LSPosed DB 里的 APK 路径并重启。
8. **中文编码**：改 Kotlin 源码/XML 用 UTF-8（勿用 PowerShell 的 `Set-Content` 默认编码，会乱码/加 BOM）。
9. **解析缓存 key 必须含完整 query**：曾用 host（甚至空串）做 key，缓存里存的是带旧 URL 的 AppTarget，30 秒内第二次复制同 host/同平台内容会复用旧 URL（表现为"打开上一个视频"）。任何把 query 存进结果的缓存，key 都要含 query。
10. **部分 app 冷启动会重写剪贴板**：如「中国移动云盘」冷启动读剪贴板里的分享链接并处理时，会把链接写回剪贴板 → 触发模块二次识别 → 气泡再弹（热启动不触发）。这是 app 行为，非模块 bug；如需避免循环，可在启动某 app 后短暂忽略同 uid 的剪贴板写入（未实现）。
11. **Provider 回写会覆盖 Settings**：配置文件缺失时 App 进程启动，Provider 内存为默认值，模块 persistSettings 会把 Settings 里的值（含 `supermi_debug`）覆盖回默认。已加**配置自愈**：`MainActivity.loadConfig` 在配置文件缺失/字段缺失时改从 Settings.System 恢复（位置/间距/图标/规则等），打开一次 app 即重建配置。
12. **app 冷启动读剪贴板**：app 只要处于前台（焦点）就能合法读剪贴板，这是 Android 允许的；"全局感知任何 app 复制"才是 system_server hook 的 root 特权，普通/非 root 方案（无障碍、Shizuku shell 身份）均围绕绕过后台读剪贴板限制展开。
